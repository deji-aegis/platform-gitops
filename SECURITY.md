# Security Policy

## Reporting a Vulnerability

Email security@example.com to report security vulnerabilities.

Do not open public issues for security findings.

## Access Control

- Write access to this repository is restricted to the platform team.
- The CI bot has write access only through pull requests, never through direct pushes to `main`.
- The `main` branch is protected by required reviews and required status checks.

## Secrets Management

- No secrets or credentials may be committed to this repository.
- All credentials must be sourced from AWS Secrets Manager or managed through External Secrets Operator.
- `imagePullSecrets` are generated by Kyverno using the configured IRSA-based identity and permissions model.

## Security Scanning

- Code, dependencies, and container images must pass the required security scans before deployment.
- Image signatures and provenance must be verified according to platform policy.
- Kubernetes manifests must pass Kyverno policy validation before deployment.

## Incident Response

Report suspected security incidents promptly to the platform security team.

Preserve relevant logs and evidence. Do not expose sensitive information in public issues or repositories.

## Policy Exceptions

Security exceptions must be documented, approved by the appropriate owner, and reviewed periodically.
